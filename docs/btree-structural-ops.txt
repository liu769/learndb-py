The goal of this doc is to explain how the btree structure changes when keys are inserted
and deleted.

The ops in questions are insert, split, delete, and compact operations, and create and delete root
operations on leaf and internal node

# Insert And Split

Given a new cell (and an included key), we find the node and cell_num on the tree
where the new cell can be placed.

Note, free space is maintained in 2 places: allocation block, and the free (linked) list.

For the new cell, we first try to provision it on the free list
    To do so, we iterate over free list and find the first block of equal or greater size.
    If we find a block, we fragment it (being mindful of minimum block size), update the free
    list, and total_space_on_free_list

If this does not satisfy, we check if the allocation block has enough space. If it does, we allocate
the cell there. Then, update the alloc_ptr

If this does not satisfy, we check if total free space (i.e. sum of all space in allocation block + free list) will
satisfy the cell. If so, we compact the node, and insert the cell.

If, the total free space on a cell does not satisfy. Then we must "split" the node. The split operation will create
2, 3 new nodes and recycle the old node.

The children nodes must be passed to parent insert method, i.e. internal_node_insert_node will have to be updated to handle
2 or 3 children.

# B-树完整操作说明

> 本文档基于 LearnDB 的 B-树实现文档整理，补全原文档未完成的部分。涵盖：插入、分裂、删除、压缩、创建根、删除根六类操作。

---

## 一、基础概念

### 1.1 节点与页

- 每个 B-树节点与一个**页（page）** 1:1 对应。
- 页是固定大小的连续块，通过 `Pager` 读写。
- 节点分为两类：
  - **叶节点（Leaf Node）**：存储实际的键值对（key → value）。
  - **内部节点（Internal Node）**：存储键 + 子节点指针，用于导航。

### 1.2 键与单元格

- **键（Key）**：表的主键，唯一且可排序。
- **值（Value）**：行中其余列的编码。
- **单元格（Cell）**：节点内存储的基本单位，包含键和值（叶节点）或键和子指针（内部节点）。

### 1.3 空闲空间的两个来源

节点内部的空闲空间维护在两个地方：

| 名称 | 含义 |
|------|------|
| **allocation block（分配块）** | 节点末尾一整块尚未分配的连续空间 |
| **free list（空闲链表）** | 删除单元格后留下的零散空闲块，用链表串起来 |

### 1.4 关键常量

在 `constants.py` 中定义：

- `LEAF_NODE_MAX_CELLS`：叶节点最多能容纳的单元格数
- `INTERNAL_NODE_MAX_CELLS`：内部节点最多能容纳的单元格数
- 最小块大小（minimum block size）：空闲链表分片时的最小剩余块

## 二、插入（Insert）

### 2.1 定位

给定新单元格（含键），从根节点开始，按键的大小逐层向下，找到**应该放置的节点**和**单元格位置（cell_num）**。

### 2.2 空间分配策略（四级渐进）

```
插入新单元格
│
├─ 1. 空闲链表有合适块？ ── 是 → 分片分配 ✅
│
├─ 2. 分配块够？ ────────── 是 → 从分配块分配 ✅
│
├─ 3. 总空闲空间够？ ────── 是 → 压缩节点后插入 ✅
│
└─ 4. 都不够 ────────────→ 分裂节点（2~3个），通知父节点
```

#### 第 1 步：从空闲链表分配

- 遍历空闲链表，找**第一个大小 ≥ 所需大小**的块。
- 找到后**分片**：切出所需大小，剩余部分留在空闲链表。
- 注意**最小块大小**：剩余太小则不切，整块分配。
- 更新空闲链表和 `total_space_on_free_list`。

#### 第 2 步：从分配块分配

- 检查分配块是否有足够空间。
- 够则直接分配，**移动 alloc_ptr**。

#### 第 3 步：压缩（Compact）

- 计算**总空闲空间** = 分配块空间 + 空闲链表空间。
- 若总空间够但无连续块，说明是**碎片化**。
- 执行 **compact**：把所有单元格紧凑重排，合并空闲空间，然后插入。

#### 第 4 步：分裂（Split）

- 若总空闲空间都不够，节点真的满了，必须**分裂**。
- 分裂创建 **2 或 3 个新节点**，回收旧节点。

### 2.3 分裂的向上传播

```
叶节点满了 → 分裂成 2~3 个节点 → 把新节点信息插入父节点
   → 父节点可能也满了 → 父节点再分裂 → 继续向上
   → 直到根节点 → 可能需要创建新根
```

- 分裂产生的子节点必须**传递给父节点的插入方法**。
- `internal_node_insert_node` 需要更新，以处理 **2 或 3 个子节点**。

---

## 三、分裂（Split）

### 3.1 触发条件

节点的**总空闲空间**（分配块 + 空闲链表）无法容纳新单元格。

### 3.2 分裂过程

1. **创建 2 或 3 个新节点**。
2. **重新分配单元格**：把旧节点的单元格（含新插入的）均匀分配到新节点。
3. **回收旧节点**：旧节点的页可以被释放或重用。
4. **向上通知**：把新节点的信息（键 + 子指针）插入父节点。

### 3.3 分裂的连锁反应

- 父节点插入新子节点后，可能也满了 → 父节点分裂。
- 递归向上，直到某个节点不需要分裂。
- 如果**根节点分裂**，需要**创建新根**（见第六节）。

### 3.4 为什么是 2 或 3 个节点？

标准 B-树通常分裂成 2 个节点。LearnDB 允许分成 2 或 3 个，可能是为了：

- 更好地利用空间（避免节点过空）
- 适应不同的节点容量和分裂策略
- 减少后续分裂频率

## 四、删除（Delete）

> 原文档未写，以下为基于 B-树原理的补全。

### 4.1 定位

从根节点开始，按键的大小逐层向下，找到**包含目标键的叶节点**和**单元格位置**。

### 4.2 删除过程

1. **从叶节点删除单元格**。
2. **更新空闲链表**：把删除的单元格空间加入空闲链表（可能与前后的空闲块合并）。
3. **更新 `total_space_on_free_list`**。

### 4.3 删除后的平衡问题

删除可能导致节点**过空（underflow）**，即单元格数低于最小值。处理策略：

#### 策略 A：借（Redistribute / Borrow）

- 如果**兄弟节点**有富余的单元格，从兄弟节点“借”一个。
- 需要更新父节点的分隔键。

#### 策略 B：合并（Merge / Coalesce）

- 如果兄弟节点也没有富余，就把当前节点和兄弟节点**合并**。
- 合并后，父节点少一个子指针，可能引发父节点也 underflow → 递归向上。

#### 策略 C：延迟处理（LearnDB 可能采用）

- 从文档看，LearnDB 的空间管理很精细（free list + compact）。
- 有可能**不立即做借/合并**，而是允许节点暂时变空，依赖后续插入时的 compact 来整理。
- 或者只在特定条件下才做合并。

### 4.4 删除根

- 如果根节点变空，且它还有子节点，**让子节点成为新根**，降低树高。
- 如果整棵树空了，根节点可以保留为空。

## 五、压缩（Compact）

### 5.1 触发条件

- 插入时，总空闲空间够但碎片化（第 3 步）。
- 或者定期/手动触发，整理节点空间。

### 5.2 压缩过程

1. **收集所有有效单元格**。
2. **紧凑重排**：把它们连续地放到节点开头。
3. **合并空闲空间**：所有空闲合并成一整块（新的分配块）。
4. **清空空闲链表**：`total_space_on_free_list` 归零。
5. **更新 alloc_ptr**：指向新的空闲起点。

### 5.3 压缩的意义

- **减少分裂**：整理碎片后，往往能腾出足够空间，避免分裂。
- **提高空间利用率**：避免节点内部碎片浪费。
- **简化后续分配**：分配块变成一整块连续空间。

---

## 六、创建根（Create Root）

### 6.1 触发条件

- **根节点分裂**：根节点满了，分裂成 2~3 个节点，需要一个新的根来指向它们。
- **空树插入第一个单元格**：需要先创建根节点。

### 6.2 创建根的过程

1. **分配新页**作为新根节点。
2. **新根是内部节点**（除非树只有一个节点）。
3. **把分裂产生的子节点**作为新根的子指针。
4. **更新树根指针**：让 B-树的根指向新节点。

### 6.3 树高的增长

- 创建新根是 B-树**长高**的唯一方式。
- 每次根分裂，树高 +1。

---

## 七、删除根（Delete Root）

### 7.1 触发条件

- **根节点变空**，且它有子节点。
- 或者整棵树被清空。

### 7.2 删除根的过程

1. **如果根是内部节点且只有一个子节点**：
   - 让这个子节点成为**新根**。
   - 回收旧根节点。
   - 树高 -1。
2. **如果根是叶节点且为空**：
   - 树变成空树。
   - 根可以保留为空叶节点，或删除。

### 7.3 树高的降低

- 删除根是 B-树**变矮**的唯一方式。
- 每次根被删除，树高 -1。

```
│                                    ↓                     │
│                              分裂向上传播                 │
│                                    ↓                     │
│                          根分裂 → 创建新根                │

```

## 九、操作对照表

| 操作 | 触发条件 | 主要效果 | 对树高的影响 |
|------|---------|---------|-------------|
| **Insert** | 新键加入 | 放入合适节点 | 不变 |
| **Split** | 节点总空间不足 | 分成 2~3 个节点 | 可能 +1（根分裂时） |
| **Delete** | 键被移除 | 从叶节点删除 | 不变 |
| **Compact** | 碎片化 | 整理空间，避免分裂 | 不变 |
| **Create Root** | 根分裂 | 新根指向分裂子节点 | +1 |
| **Delete Root** | 根变空 | 子节点成为新根 | -1 |

---

## 十、设计要点总结

1. **空间管理精细**：allocation block + free list 双层结构，类似内存分配器。
2. **渐进策略**：插入时由廉价到昂贵——复用碎片 → 连续块 → 压缩 → 分裂。
3. **compact 是关键优化**：在分裂前整理碎片，显著减少分裂次数。
4. **分裂产生 2~3 个节点**：非标准设计，可能为了更好的空间分布。
5. **树高变化只在根**：只有创建根（+1）和删除根（-1）会改变树高。
6. **删除的平衡策略**：可能采用借/合并，也可能延迟处理，依赖 compact 整理。
